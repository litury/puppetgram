# Автоматическое комментирование с ротацией аккаунтов

## Назначение

Скрипт `comment:auto` предназначен для автоматического размещения комментариев в каналах Telegram с использованием нескольких аккаунтов по очереди. Система автоматически переключается между аккаунтами для распределения нагрузки и избежания блокировок.

## Предварительные требования

### Очередь по подписчикам

Для нового прохода задайте `PROCESS_MODE=subscribers` в env комментатора.
В очередь входят каналы с `participants >= 1000` и `comments_state = 'open'`,
включая новые и ранее обработанные, независимо от наличия просмотров.
Верхнего ограничения аудитории нет. Каналы с неизвестным числом подписчиков,
непроверенными или закрытыми комментариями в эту очередь не попадают.

Сортировка: `subscribers_pass ASC`, затем `participants DESC`, затем `id ASC`.
Отдельный счётчик начинается с нуля и сохраняется между партиями и рестартами:
прежний `done_views_pass` не влияет на новый проход. Публикация, обнаружение
существующего комментария и обработанная ошибка завершают посещение;
FLOOD_WAIT оставляет посещение незавершённым. Существующий комментарий не
считается новой публикацией. После обхода пула начинается следующий проход.
Расчёт рассчитан на один экземпляр комментатора.

Миграция `003_subscribers_pass` применяется при запуске сервиса и добавляет
счётчик с индексом. Для переключения существующего Dokploy-приложения нужно
изменить его `PROCESS_MODE=done` на `PROCESS_MODE=subscribers` и задеплоить код.
Прежние режимы `new` и `done` остаются доступны.

Интеграционная проверка на отдельной тестовой PostgreSQL:
`TEST_DATABASE_URL=postgresql://... npx ts-node src/scripts/utils/testSubscriberQueue.ts`.
Тест использует отдельную схему внутри транзакции и откатывает её после проверки.

### Хранитель и Premium

`ROTATION_TARGET_ACCOUNT=viknick7` назначает аккаунт только хранителем канала.
Он остаётся в пуле `commenter` с паролем 2FA для передачи владения, но исключён
из комментариев и выбора рабочих аккаунтов. При отсутствии свободных работников
канал возвращается хранителю до ожидания разблокировки. Когда работник доступен,
он получает канал после проверки спама и Premium. По завершении очереди канал
также возвращается хранителю.

Спам-метка и FLOOD_WAIT комментирования хранителя не запрещают попытку передачи
ему канала. Ограничения самого Telegram на передачу продолжают действовать;
ошибка передачи не считается успехом.

У рабочих аккаунтов Premium проверяется через Telegram `getMe()` перед началом
работы и затем раз в пять минут. `SEND_AS_PEER_INVALID` запускает внеочередную
проверку. Только подтверждённое отсутствие Premium ставит статус `no_premium`
в БД и исключает аккаунт из работы, включая аккаунты из env. Ошибка Telegram
сама по себе не означает отсутствие Premium. После покупки Premium верните
аккаунту статус `active` и перезапустите комментатор для повторной проверки.
Хранителю Premium для этой роли не требуется.

Локальная проверка ротации без Telegram и БД:
`npx ts-node src/scripts/utils/testCommenterKeeper.ts`.

### API ключи и сервисы
- **DEEPSEEK_API_KEY** - для генерации умных комментариев с ИИ
- **API_ID** и **API_HASH** - учетные данные Telegram API

### Настройка аккаунтов
- **Минимум 2 аккаунта** в файле `.env` для эффективной ротации
- Все аккаунты должны иметь активные сессии
- Рекомендуется 3-5 аккаунтов для оптимальной ротации

### Подготовка каналов
- **Файл каналов**: `input-channels/channels.txt`
- Каналы должны разрешать комментирование
- Формат: один канал на строку (@username или ссылка)

## Команда запуска

```bash
npm run comment:auto
```

## Пошаговый процесс выполнения

### Шаг 1: Загрузка аккаунтов
```
🚀 Автокомментатор | 4 акк | лимит 190

📋 Загружено 47 каналов
```
**Процесс**: Система автоматически загружает все аккаунты и список каналов

### Шаг 2: Загрузка списка каналов
```
📋 ЗАГРУЗКА КАНАЛОВ
✅ Загружено каналов: 47
📁 Источник: input-channels/channels.txt

📺 Примеры каналов:
- @cryptonews
- @techblog_ru
- @startup_digest
```
**Требование**: Убедитесь что файл `input-channels/channels.txt` содержит актуальный список каналов

### Шаг 3: Выбор количества каналов для комментирования
```
🔍 ПАРАМЕТРЫ КОММЕНТИРОВАНИЯ
Сколько каналов обработать? (всего 47): [20]
> 15
```
**Действие**: Введите желаемое количество каналов или используйте значение по умолчанию

### Шаг 4: Автоматическое комментирование с ротацией
```
🎯 Аккаунт: Пользователь1 (@user1_example)
📺 Канал: IT Новости (@it_news_digest)
📨 Последний пост: "Новые возможности в Python 3.13"
🤖 Генерирую комментарий...
💬 Комментарий: "Интересные обновления! Особенно впечатляет улучшение производительности JIT-компилятора."
✅ Комментарий размещен

🔄 Переключение на следующий аккаунт: Пользователь2 (@user2_example)
⏱️ Пауза между аккаунтами: 15 секунд...
```

### Шаг 5: Ротация аккаунтов

## Входные параметры

### Интерактивные параметры
- **Количество каналов** для обработки (по умолчанию: 20)

### Конфигурационные параметры
- **Пауза между комментариями**: 15-30 секунд
- **Пауза между аккаунтами**: 10-20 секунд
- **Пауза между каналами**: 5-10 секунд
- **Максимум постов для анализа**: 3 последних поста
- **Timeout для ИИ**: 20 секунд

### Файлы конфигурации
- **rotation-state.json** - состояние ротации аккаунтов
- **input-channels/channels.txt** - список каналов для комментирования
- **input-channels/successful-channels.txt** - каналы где комментирование успешно

## Результат работы

### Размещенные комментарии
- **Умные комментарии** сгенерированные ИИ на основе контента поста
- **Разнообразие стилей** для каждого аккаунта
- **Релевантность** теме и контексту обсуждения

### Обновленные файлы
- **rotation-state.json** - сохранение текущего состояния ротации
- **input-channels/successful-channels.txt** - добавление успешно обработанных каналов
- **Логи активности** для каждого аккаунта

### Системы защиты
- **Проверка на дубликаты** - исключение повторного комментирования
- **Обнаружение спама** - пропуск каналов с подозрительным контентом
- **FloodWait handling** - автоматические паузы при ограничениях

## Алгоритм ротации

### Принцип работы
1. **Циклическое переключение** между всеми активными аккаунтами
2. **Равномерное распределение** нагрузки
3. **Сохранение состояния** между запусками скрипта
4. **Восстановление позиции** после перезапуска

### Логика выбора аккаунта
```
Аккаунт 1 → Аккаунт 2 → Аккаунт 3 → Аккаунт 4 → Аккаунт 1 ...
    ↓           ↓           ↓           ↓           ↓
  Канал 1    Канал 2    Канал 3    Канал 4    Канал 5
```

### Файл состояния (rotation-state.json)
```json
{
  "currentAccountIndex": 2,
  "accountStats": {
    "user1_example": {"comments": 15, "lastUsed": "2025-01-14T10:30:00Z"},

    "user3_example": {"comments": 18, "lastUsed": "2025-01-14T10:35:00Z"}
  },
  "lastRotationTime": "2025-01-14T10:35:00Z"
```

## Защита от спама и блокировок

### Встроенные механизмы
- **Проверка дубликатов** перед размещением
- **Анализ контента** на соответствие теме
- **Вариативность комментариев** для каждого аккаунта
- **Соблюдение временных интервалов**

### Пропуск нежелательных каналов
- **Спам-каналы** с подозрительным контентом
- **Каналы без активности** (более 7 дней без постов)
- **Каналы с заблокированными комментариями**
- **Каналы где аккаунт уже комментировал**

## Частые проблемы и решения

### FloodWait ошибки
**Проблема**: `FLOOD_WAIT_X: подождите X секунд`
**Решение**: Система автоматически ждет указанное время и продолжает

### Комментарии не размещаются
**Проблемы и решения**:
1. **Канал запретил комментирование** - канал автоматически пропускается
2. **Аккаунт не подписан** - добавьте подписку или пропустите канал
3. **Превышены лимиты** - увеличьте паузы между комментариями

### Ошибки ИИ генерации
**Проблема**: `API Error: Rate limit exceeded`
**Решение**: Уменьшите количество каналов или увеличьте паузы

### Проблемы с ротацией
**Проблема**: Используется только один аккаунт
**Решения**:
1. Проверьте `.env` файл на наличие нескольких аккаунтов
2. Убедитесь что все сессии валидны
3. Удалите `rotation-state.json` для сброса состояния

## Настройка и оптимизация

### Рекомендуемые паузы
- **Малая нагрузка** (1-2 аккаунта): 30-60 секунд между комментариями
- **Средняя нагрузка** (3-4 аккаунта): 15-30 секунд между комментариями
- **Высокая нагрузка** (5+ аккаунтов): 10-20 секунд между комментариями

### Оптимальное количество аккаунтов
- **Минимум**: 2 аккаунта для базовой ротации
- **Рекомендуется**: 3-4 аккаунта для эффективной работы
- **Максимум**: 7-8 аккаунтов (больше может привлечь внимание)

### Периодичность использования
- **Ежедневно**: 10-20 каналов при наличии 3+ аккаунтов
- **Через день**: 20-30 каналов при наличии 4+ аккаунтов
- **Еженедельно**: 50-100 каналов при наличии 5+ аккаунтов
